## Gaps (unresolved)

- `solder_paste_rel_margin` value encoding: the parser runs the value through the dimensional unit resolver (it is not in the unitless or ratio lists), while PAD divides the stored opt by 1000 to get a ratio. How to write a non-zero relative margin in a .kicad_dru is unresolved; the only sourced value is `(opt 0mm)` in a QA test (pcbnew/drc/drc_rule_parser.cpp:612-619; pcbnew/pad.cpp:2064†; qa/tests/pcbnew/test_libeval_compiler.cpp:719).
- `solder_mask_sliver` is parsed and offered by the graphical editor, but no consumer was found in pcbnew/*.cpp or common/*.cpp at this commit (other directories such as plotting code under other paths were not fetched). Whether any check enforces it is unresolved.
- `DIFF_PAIR_INTRA_SKEW_CONSTRAINT` has no DRU keyword and no consumer beyond the API enum conversion; its intended future use is unknown.
- `(time_domain yes)` (help) is concluded to be a parse error from reading the parser and the keyword list; not confirmed by running KiCad.
- Operator precedence (`&&` lower than `||`) is inferred from lemon declaration order in grammar.lemon; not confirmed by running an expression.
- The help suggests `(min -1)` for overlapping clearance; by the code a lone unitless number reports 'Missing units'. Not confirmed by running KiCad.
- MINOPTMAX defaults (include/core/minoptmax.h) are not in the checkout, so the effective value of a constraint with an unset min/opt/max (e.g. the implicit courtyard rule, or a `thermal_spoke_width` rule that sets only min while the zone filler reads opt) is unverified.
- Property rows list the class that registers each property; inheritance is given in the class rows, but SetAvailableFunc predicates (marked 'has an availability predicate') were not evaluated, and dynamic properties (PROPERTY_MANAGER::GetProperty on an object) are not reachable from rule expressions and were not enumerated.
- Enum choice labels were extracted only where an ENUM_MAP<...>::Instance().Map(...) chain is in pcbnew/common .cpp files; enums without such a chain (e.g. text justification) are listed as 'choice labels not extracted'.
- The violation key for `net_chain_length` (length_out_of_range) is inferred from the matched-length provider's code set, not traced to the exact report call.
- 'Applies to' is taken from help text, the engine's show-match domains and the providers' type filters; per-provider item filters were not traced exhaustively.
- Release vocabularies exist only for 9.0 and 10.0; differences for 6.x-8.x cannot be stated from these sources (docs.kicad.org is blocked).
